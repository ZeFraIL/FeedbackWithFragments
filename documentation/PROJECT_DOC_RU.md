## 🎯 Цель проекта
•   **Задача:** Предоставление пользователю удобного интерфейса для отправки обратной связи через различные каналы связи (SMS, E-mail, Телефон).
•   **Важность:** Централизация методов связи в одном приложении упрощает взаимодействие пользователя с поддержкой или автором.
•   **Целевая аудитория:** Пользователи мобильных приложений, которым требуется быстрый доступ к контактам.
________________________________________
## 📌 Требования к приложению
### Функциональные требования
•   Переключение между экранами ввода без перезагрузки всей активности.
•   Автоматическая проверка доступности сети и блокировка недоступных функций.
•   Ввод текста и номера телефона для SMS.
### Нефункциональные требования
•   **Производительность:** Мгновенное переключение фрагментов.
•   **Удобство:** Интуитивно понятные кнопки управления в нижней части экрана.
•   **Надёжность:** Предотвращение попыток отправки данных при отсутствии связи.
________________________________________
## 🧠 Общая архитектура
•   **Выбранный подход:** MVC (Model-View-Controller).
•   **Почему:** Для небольшого проекта это позволяет четко разделить логику управления (Activity) и интерфейс (Fragments).
•   **Компоненты:**
    *   `MainActivity` — Контроллер.
    *   `Fragments` — Представления (Views).
    *   `BroadcastReceivers` — Слушатели системных событий.
________________________________________
## 🧩 UML-диаграмма
`[MainActivity]` <--> `[SMSFragment | MailFragment | PhoneFragment]`
`[MainActivity]` <-- `[ConnectivityManager]`
________________________________________
## 🧩 Подробное описание классов
### 📌 Класс: MainActivity
*   **Роль:** Главный хаб и координатор.
*   **Ответственность:** Управление жизненным циклом фрагментов, регистрация ресиверов сети.
*   **Методы:**
    *   `onCreate()` — инициализация элементов и установка слушателей.
    *   `updateButtonsState()` — логика проверки доступности мобильной сети.
    *   `onResume()` / `onPause()` — управление системными подписками.

### 📌 Класс: SMSFragment / MailFragment / PhoneFragment
*   **Роль:** Модули интерфейса.
*   **Ответственность:** Сбор данных от пользователя.

## 🎨 UI/UX анализ
•   **Принципы:**
    *   **Простота:** Одна кнопка — одно действие.
    *   **Логичность:** Область контента находится над кнопками управления.
    *   **Доступность:** Визуальная блокировка кнопок (disabled state), если функция недоступна.
________________________________________
## ⚙️ Работа с потоками
•   **Способ:** Основной поток (UI Thread).
•   **Предотвращение ANR:** Использование легковесных операций внутри BroadcastReceiver.
________________________________________
## 💾 Работа с данными
•   **Тип:** Временное хранение в UI-компонентах (EditText).
•   **Безопасность:** Данные не сохраняются на диске, что исключает их утечку после закрытия приложения.
